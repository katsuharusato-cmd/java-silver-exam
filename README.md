# Java Silver 模擬試験アプリ

Spring Boot (Java 17) + Thymeleaf で作成した、Pearson VUE の CBT試験画面をイメージした
Java Silver 模擬試験シミュレーターです。

## 起動方法

```bash
# 依存関係のダウンロード〜起動まで（Maven Wrapperが無い場合は事前に mvn をインストール）
mvn spring-boot:run
```

起動後、ブラウザで `http://localhost:8080/` にアクセスしてください。

jar化して起動する場合：

```bash
mvn clean package
java -jar target/java-silver-exam-1.0.0.jar
```

## 問題の追加・編集方法

`src/main/resources/questions.yml` に問題データが入っています。
ファイル冒頭にコメントで書式の説明があります。1問につき次のような形式です。

```yaml
- id: 1
  category: 1
  description: |
    次のコードをコンパイル、実行した結果として正しいものを選びなさい。
  code: |
    public class Sample {
        public static void main(String[] args) {
            System.out.println("Hello");
        }
    }
  options:
    - id: a
      text: "Hello と表示される"
    - id: b
      text: "コンパイルエラーになる"
    - id: c
      text: "実行時に例外がスローされる"
    - id: d
      text: "何も表示されない"
  answers: [a]
```

- `category` は分野番号（数値）です。分野名との対応は `ExamCategory.java` を参照してください。
- `code` はソースコードが無い問題であれば `code:` の行ごと削除してかまいません。
- `answers` に選択肢idを2つ以上書くと、自動的に複数選択問題（選べる最大数=正解の数）になります。
- 現在は60問分のプレースホルダー（サンプル文言）が入っているので、
  `description` / `code` / `options` / `answers` の中身をご自身の問題内容に書き換えてください。
- `id` は重複しないようにしてください（出題順のランダム化に使われます）。

## Slackログインのセットアップ（現在は未使用・参考情報）

> **現在、ログイン方法は「名前だけで入るゲストログイン」のみを使う設定にしています。**
> スタートページからSlackログインのボタンは非表示にしました。以下はSlackログインを
> 再度使いたくなったときのための手順です（コード自体は残しているので、いつでも復活できます）。

このアプリは「Sign in with Slack」（SlackのOAuth 2.0 / OpenID Connect）を使ってログインする
こともできます。流れはシンプルです：

**ログインリンクを踏む → Slackのワークスペースにサインイン → 「Slackへのアクセスを許可する」画面で許可
→ このアプリにログインした状態で戻ってくる**

これを動かすために必要な設定は、次の4ステップだけです。

### セットアップ手順

**0. Slack Appを新規作成する**

https://api.slack.com/apps を開き、「Create New App」→ワークスペースを選んで作成します。

**1. Redirect URL を登録する**

左メニューの「OAuth & Permissions」で、Redirect URLs にこのアプリのコールバックURLを追加します。

```
http://localhost:8080/login/oauth2/code/slack
```

（本番ドメインで動かす場合は `https://<ドメイン>/login/oauth2/code/slack` に置き換えてください）

このパス（`/login/oauth2/code/slack`）はSpring Security側の標準パスなので、アプリのコード側は
変更不要です。ドメイン部分だけ実際の環境に合わせてください。

**2. Scopes を設定する**

`openid`、`profile`、`email` の3つを追加します。

**3. Client ID / Client Secret を環境変数に設定してバックエンドを起動する**

「Basic Information」に表示される Client ID と Client Secret を控えて、環境変数として渡します。

```bash
export SLACK_CLIENT_ID=xxxxxxxxxx.xxxxxxxxxx
export SLACK_CLIENT_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
mvn spring-boot:run
```

これで完了です。`http://localhost:8080/` を開き、「Slackで連携してログイン」ボタン
（または `http://localhost:8080/login/slack` へのリンク）から、スクリーンショットにあったような
Slackのサインイン画面 → 許可画面 → ログイン、という流れになります。

環境変数を設定しない場合は `application.yml` のダミー値のままになり、ログインボタンを押すと
Slack側でエラーになります（アプリの起動自体はClient ID/Secretが無くても可能です）。

### Slack側に貼っておくリンクについて

SlackのチャンネルやApp Homeなどに貼っておくリンクは、次のURLにしてください。

```
http://localhost:8080/login/slack
```

（本番の場合はそのドメインに置き換え）。このURLは内部で自動的に `/oauth2/authorization/slack` へ
転送されるだけの入り口で、Slackに既にログイン済みの状態でクリックすれば、追加のID/パスワード入力なしに
そのまま許可画面が表示されます。

## データの保存先について（PostgreSQLへの移行は一旦見送り）

問題データ（`questions.yml`）と受験履歴は、外部セットアップが不要な**組み込みDB（H2）**で
管理しています。以前PostgreSQLへの移行を試みましたが、環境構築（パスワード認証エラー等）で
うまくいかなかったため、いったん元の方式に戻しました。

- **問題データ**：`questions.yml` を起動時に読み込み、アプリのメモリ上に保持するだけです
  （DBへの保存はしていません）。問題を追加・修正したいときは、`questions.yml` を編集して
  アプリを再起動してください。
- **受験履歴**：H2データベース（`./data/examdb` にファイルとして自動生成）に保存されます。
  Dockerや外部DBのセットアップは一切不要で、`mvn spring-boot:run` するだけで動きます。

PostgreSQLへの移行を再検討したくなったら、いつでも声をかけてください
（`spring.datasource` の設定を差し替えるだけで、コード側は同じ形に戻せます）。

## 受験履歴について

- ログインしているユーザー（名前）ごとに、試験を終了するたびに「受験日時／正答数／正答率」が
  H2データベース（`./data/examdb` にファイル保存）に記録されます。
- ヘッダーの「受験履歴」リンク（試験を解いている画面では非表示）、スタートページの「受験履歴を見る」、
  結果ページの「受験履歴をすべて見る」から確認できます。
- 受験履歴ページからは「スタートページへ戻る」でいつでも注意書きのページに戻れます。
- サーバーを再起動しても履歴は保持されます（`data/` フォルダを削除するとリセットされます）。
- 未ログイン状態では `/exam/...` 配下のページには一切アクセスできず、スタートページで
  ログイン（名前入力）を求められます。
- ログアウト時は確認ポップアップが出ます（試験が中断され、現在の回答記録は残らない旨を表示）。

## ゲスト（名前だけ）ログインについて

- 現在は、これが**唯一のログイン方法**です。スタートページで名前を入力するだけでログインでき、
  同じ名前を入力すれば同じ人として履歴が積み上がる仕様です。
- 無効化したい場合は `application.yml` の `app.demo-login-enabled` を `false` にしてください
  （ただし現状Slackログインを無効化しているため、`false`にすると誰もログインできなくなる
  点に注意してください。Slackログインを復活させてから無効化するのがおすすめです）。
- **セキュリティ面**：認証局を介さない自己申告制なので、名前が本人確認になっていません。
  同じ名前を誰でも名乗れてしまう（他人の履歴に見える形で結果が積み上がる可能性がある）点は
  リスクとして認識しておいてください。社外に公開する環境では特に注意し、社内ネットワーク
  限定でのアクセスや、VPN経由などネットワークレベルでの制限と組み合わせることをおすすめします。
  漏れて困るような機密情報を扱うわけではないため、社内限定の練習アプリとして使う分には
  実用上大きな問題にはならないと考えられます。
- **サーバー負荷面**：ゲストログインはセッションを1つ作るだけなので、通常のログインユーザーが
  増えるのと同程度の負荷であり、特別に負荷が増えるようなことはありません。

## 分野（カテゴリ）別の出題・集計について

- `questions.yml` の各問題に `category`（数値）を追加しています。番号と分野名の対応は
  `com.exam.silver.model.ExamCategory` で定義しており、Java Silver試験の出題範囲に
  準拠した以下の6分野になっています。

  | 番号 | 分野名 |
  |---|---|
  | 1 | Javaの概要と簡単なJavaプログラムの作成 |
  | 2 | Javaの基本データ型と文字列の操作 |
  | 3 | 演算子と制御構造 |
  | 4 | クラスの定義とインスタンスの使用 |
  | 5 | 継承とインタフェースの使用 |
  | 6 | 例外処理 |

- 現時点では出題比率の重み付けまでは行っておらず、あくまで結果ページでの分野別集計
  （正答率の可視化）に使っています。将来、分野ごとの出題比率を実際の試験に合わせたい場合は、
  `ExamController#startExam()` のシャッフルロジックを分野別に重み付けする形に拡張してください。

## 実装している主な仕様

- スタートページ（試験の注意書き）→「試験を始める」で試験開始。「受験履歴を見る」ボタンも配置
- 問題は1ページ1問、縦スクロールで閲覧、チェックボックス選択式（単一・複数どちらも対応）
- 試験開始時に問題順をランダム化し、以降は固定
- 回答・「後で見る」チェックは画面遷移しても保持
- 右上に残り時間カウントダウン（90:00からカウントダウン）、現在の問題番号 (n/60) と進捗バー
- 「後で見る」チェックボックス（少し大きめサイズ）
- 「試験を終了する」ボタン（クリックで確認モーダル表示）→ 終了で採点・結果表示
- 終了後は「試験を終了する」ボタンが「新しく試験を始める」ボタンに変化
- 「全問題レビュー」ページ：回答状況・後で見るフラグの一覧、採点後は正解/不正解も表示
  （未回答は赤字・各ステータスは太字で強調）
- 「後で見る」だけに絞って前へ/次へ移動できるフィルターチェックボックス
- 採点後は問題ページに戻ると自分の回答と正解を見比べられる
- 結果ページに、分野別正答率のグラフ、過去の受験結果との比較（推移グラフ・前回比）、
  直近の受験履歴を表示
- 背景白・文字黒、モノスペース系フォント＋アンチエイリアス無効化で「ざらざら」した古いPC風の見た目
- 名前だけで入れるゲストログイン（現在の唯一のログイン方法。Slackログインのコードは
  残しているのでいつでも復活可能）
- ログインユーザーごとの受験履歴をデータベース（H2）に保存し、あとから一覧・グラフで確認可能
- ログアウト時に確認ポップアップを表示（試験中断・回答記録が残らない旨を明示）
